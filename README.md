## Application

Уншлагын жагсаалт вэб аппын UI болон API-г exploratory testing аргаар шалгав.

## Testing approach

- Supermodel: үндсэн хэрэглэгчийн үйлдлүүд
- Couch Potato: хоосон болон буруу оролтууд
- Saboteur: хүчингүй JSON болон API-ийн хариу
- Fed-Ex: ном нэмэх, хайх, устгах, жагсаалт ба статистик

## Findings

1. Invalid JSON хүсэлтэд HTTP 200 буцаасан.
2. Хоосон жагсаалтын нийт номын тоо 1 гэж харагдсан.
3. Хоосон талбартай ном нэмэгдсэн.
4. `abc` гэсэн оны утгыг зөвшөөрсөн.
5. Ижил гарчиг, зохиогчтой номыг давхар нэмэх боломжтой байсан.

Дэлгэрэнгүй: `bugs/` хавтас.

## Debrief

Энэ session-ийн үеэр аппын ном нэмэх, статистик болон API-ийн ажиллагааг шалгав. Буруу JSON хүсэлтэд сервер HTTP 200 буцааж байгааг curl ашиглан илрүүлэв. Хүснэгт хоосон байхад нийт номын тоо 1 гэж харагдсан. Хоосон талбаруудыг бөглөөгүй үед ном нэмэгдэж байв. Мөн `abc` гэсэн оны утгыг апп зөвшөөрсөн. Ижил гарчиг, зохиогчтой номыг хоёр удаа нэмэх боломжтой байв. Эдгээр үр дүнг bug report болон боломжтой screenshot-уудаар баримтжуулав. Дараагийн шатанд хилийн утгууд болон урт текстийн оролтыг илүү нарийвчлан турших шаардлагатай. Playwright тестүүд давтагддаг баталгаажуулалт, API статус болон өгөгдлийн нөхцөлийг автоматжуулж чадна. Харин layout, мессежийн ойлгомжтой байдал болон харагдах байдлын зарим асуудлыг хүн нүдээр шалгах нь тустай.
